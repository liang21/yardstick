## 一、为什么这是分水岭

阶段 1 结束时，你能跑分了。但有两个问题没解决：

1. **凭什么相信这 50 条能代表线上？** —— 评测集的代表性
2. **凭什么相信自动打的分？** —— judge 的可信度

绝大多数做 AI 评测的人卡在这里：他们会调 Ragas，但答不出"你的 judge 和人类判断的一致性是多少"。**这个数字，就是你的护城河。**

一句话概括本阶段：

> **评测系统本身也需要被评测。** 你要拿出证据证明你的尺子是准的，而不是拿一把没校准的尺子去量别人。

## 三、W1–W2：评测集工程

### 3.1 评测集的三个来源，按价值排序

| 来源 | 价值 | 注意 |
|---|---|---|
| **线上真实 query 日志** | 最高。真实分布、真实措辞、真实错别字 | 必须脱敏；要抽样而非只挑典型 |
| **业务方/客服提供的高频问题** | 高。代表业务重点 | 往往偏"标准问法"，需要口语化改写 |
| **人工构造的边界与对抗 case** | 高。自动生成造不出来 | 别构造得过于刁钻，要保持真实性 |
| 从文档反推的问题 | 低。天然可答，缺乏区分度 | 只用来补基础覆盖 |
| 模型批量生成 | 最低 | 仅用于扩充已有类型的变体，且必须人工过一遍 |

### 3.2 分层设计：三个正交维度

不要只按"问题类型"分。用三个维度交叉：

**维度 A：意图/场景类型**（跟着业务走）

以客服场景为例：查询类、操作指引类、政策解释类、故障排查类、投诉抱怨类、闲聊类。

**维度 B：难度**

| 难度 | 定义 |
|---|---|
| easy | 单跳，文档里有明确表述 |
| medium | 需要跨段落整合，或需要推理 |
| hard | 多跳、需要条件判断、表述分散 |

**维度 C：可答性与对抗性**

| 类别 | 目标占比 | 说明 |
|---|---|---|
| 正常可答 | 50% | 基本盘，保证不倒退 |
| 无答案（unanswerable） | 15% | 文档里确实没有 |
| 前提错误（false premise） | 8% | 问题本身的假设是错的 |
| 歧义（ambiguous） | 7% | 需要澄清而非猜测 |
| 精确标识符 | 5% | 订单号、错误码、版本号 |
| 口语化/错别字/多意图 | 10% | 真实用户的样子 |
| 超范围（out of scope） | 5% | 该礼貌拒绝 |

**200 条的分配建议**：先按维度 C 定总量，再保证每个意图类型至少 15 条，难度分布大致 4:4:2。

### 3.3 几类难写的 case，给具体写法

**无答案问题 —— 要"高相似度但无答案"**

- 差：问"今天天气怎么样" → 检索不到任何东西，太容易拒答
- 好：文档写了"退款流程"但没写"退款失败怎么办" → 会检索到一堆高相似度的退款段落，模型极易顺势编造

**前提错误问题**

> 文档：退款 7 个工作日到账
> 问题：为什么你们退款要等 30 天这么久？

三种行为，要分档：纠正前提（最好）→ 回避不纠正（中）→ 顺着编理由（最差）。这类 case 必须在 rubric 里有明确档位定义。

**歧义问题**

> "会员怎么取消" —— 是取消自动续费，还是注销会员资格？

理想行为是反问澄清。但要注意：**如果产品定位就是一问一答不支持反问，那理想行为就是给出覆盖两种解释的答案**。行为标准取决于产品，不是绝对的。

**多意图问题**

> "我订单还没发货，另外我想改收货地址，还有你们客服电话多少"

考的是完整性。常见失败是只答第一个问题。

### 3.4 元数据 schema（在阶段 1 基础上扩展）

```jsonl

  "question": "我昨天下的单，钱扣了但订单没了，是不是被吞了",
```

`expected_behavior` / `forbidden_behavior` 是为 judge 准备的——比一句笼统的 gold_answer 更能指导打分。

### 3.5 代表性论证（面试高频题的答案来源）

"你怎么证明你的评测集有代表性？"——这题不能答"我覆盖了各种类型"，要拿数据。

**做三个分布对齐**：

```python
import pandas as pd
from scipy.stats import ks_2samp

online = pd.read_json("data/online_queries_sample.jsonl", lines=True)
evalset = pd.read_json("data/eval_set_v1.jsonl", lines=True)

# 1. 意图分布对齐
cmp = pd.DataFrame({
    "线上": online["intent"].value_counts(normalize=True),
    "评测集": evalset["intent"].value_counts(normalize=True),
}).fillna(0)
cmp["差值"] = (cmp["评测集"] - cmp["线上"]).round(3)
print(cmp.sort_values("差值", key=abs, ascending=False))

# 2. 长度分布对齐（KS 检验）
stat, p = ks_2samp(online["question"].str.len(), evalset["question"].str.len())
print(f"长度分布 KS 统计量={stat:.3f}, p={p:.3f}")   # p 大说明分布无显著差异

# 3. 覆盖率：线上高频 query 聚类后，评测集覆盖了多少簇
```

**报告怎么写**：

> 评测集意图分布与线上 8 月样本对齐，最大偏差 4.2 个百分点（"投诉抱怨"类刻意上采样，因该类失败代价最高）；问题长度分布 KS 检验 p=0.31，无显著差异；线上 query 聚类得到 47 个语义簇，评测集覆盖 43 个（91%），未覆盖的 4 个簇均为单次出现的长尾。

**注意"刻意偏离"是允许的，但必须说明理由。** 高风险类别上采样是正常做法，藏着不说才是问题。

### 3.6 数据污染与泄漏

三种要防的情况：

1. **评测集进了训练/微调数据** —— 如果团队会用线上日志微调，评测集来源的那批日志必须打标隔离
2. **评测集公开泄漏** —— 别把含 gold_answer 的评测集贴到公开仓库或发给外部模型厂商
3. **prompt 里泄漏** —— 调试时把 gold_answer 写进 few-shot，然后忘了删

建立习惯：**评测集单独仓库/目录，明确标注"不得进入任何训练流程"**。

### 3.7 版本化与变更管理

评测集会一直变（阶段 5 还要回流线上 bad case）。从现在开始：

- 文件名带版本：`eval_set_v1.jsonl`
- 每条 case 有 `version` 和 `added_at`
- 变更写 CHANGELOG：加了什么、删了什么、**为什么**
- **重要规则：修改评测集后，历史分数不能直接和新分数比较。** 必须标注"此分数基于 eval_set_v1"。这是阶段 4 回归的前提。

2. 做三个分布对齐，写出代表性论证段落
3. 建立版本化目录结构和 CHANGELOG
4. **自检**：随机抽 20 条隔天重判，记录自己改主意的比例

## 四、W3：rubric 设计与人工标注

### 4.1 rubric 的四条设计原则

**原则 1：描述可观察行为，不描述主观感受**

- 差：「回答质量好」「用户体验流畅」
- 好：「回答包含全部 3 个关键要点，且无文档外信息」

**原则 2：维度分离，不要一个总分**

把质量拆成正交维度，各自独立打分：

| 维度 | 问什么 |
|---|---|
| **正确性** | 说的对不对 |
| **完整性** | 该说的说全了没有 |
| **忠实度** | 有没有超出文档编造 |
| **相关性** | 有没有答到点上 |
| **可操作性** | 用户看完知不知道下一步做什么 |
| **格式/语气** | 是否符合产品调性 |

不必全用，选 3–4 个和业务最相关的。**分维度的最大好处：judge 更容易和人对齐，且低分时能直接定位问题。**

**原则 3：档位用 3–5 档，不用 1–10**

人类在细粒度上一致性会崩溃——两个标注者对"7 分还是 8 分"基本是随机的。3–5 档且每档有明确锚点，一致性会高得多。

**原则 4：每档给锚点例子**

只写档位定义不够，必须配真实例子。这些例子后面直接复用为 judge 的 few-shot。

### 4.2 可套用的 rubric 模板

```markdown
# 客服问答质量评分规范 v1

## 打分前的前置判断

先判断本题类别，不同类别用不同标准：
- 【可答】→ 走维度 1–4
- 【无答案】→ 只看"是否正确拒答"，正确拒答直接记满分，编造直接记 1 分
- 【前提错误】→ 只看"是否纠正前提"
- 【超范围】→ 只看"是否礼貌拒绝并引导"

## 维度 1：正确性（1–4 分）

| 分 | 定义 | 锚点例子 |
|---|---|---|
| 4 | 全部陈述与文档一致，无错误 | （粘真实答案） |
| 3 | 主要陈述正确，有次要细节偏差，不影响用户决策 | （粘） |
| 2 | 存在会误导用户的错误陈述 | （粘） |
| 1 | 主要结论错误，或大段编造 | （粘） |

## 维度 2：完整性（1–4 分）

按 gold_facts 命中数判定：
| 分 | 定义 |
|---|---|
| 4 | 覆盖全部要点 |
| 3 | 覆盖 ≥2/3 要点，遗漏的不影响主要决策 |
| 2 | 覆盖 <2/3，或遗漏了关键前置条件 |
| 1 | 只覆盖 ≤1/3 |

## 维度 3：忠实度（1–4 分）
（同上结构）

## 维度 4：可操作性（1–4 分）
（同上结构）

## 争议处理
- 拿不准时，问："一个真实用户看到这个回答，会不会做出错误的行动？"会 → 不高于 2 分
- 两人分歧 ≥2 档 → 记入争议清单，集中讨论后更新本规范
```

### 4.3 标注流程（不要直接开标）

```
第 1 步：试标 20 条（你 + 另一人各自独立）
    ↓
第 2 步：对分歧逐条讨论，找出是「标准不清」还是「理解不同」
    ↓
第 3 步：改 rubric，补锚点例子
    ↓
第 4 步：再试标 20 条新的，算 Kappa
    ↓  Kappa < 0.6 → 回到第 2 步
    ↓  Kappa ≥ 0.6
第 5 步：正式标注全部 200 条（你标全部，对方标其中 50 条做交叉验证）
```

**关键点：不要在同一批 20 条上反复迭代**，那会过拟合到这 20 条。每轮换新的。

### 4.4 一致性统计：用对指标

这是很多人做错的地方。

| 场景 | 该用什么 | 不该用什么 |
|---|---|---|
| 两人，有序分数（1–4 档） | **Quadratic Weighted Kappa** | 普通 Cohen's Kappa（它把"3vs4"和"1vs4"视为同等分歧，不合理） |
| 两人，二分类（通过/不通过） | Cohen's Kappa | 单纯准确率（类别不平衡时虚高） |
| 三人以上，或有缺失 | Krippendorff's alpha | Cohen's Kappa（只支持两人） |
| 连续分数 | Spearman / Pearson | Kappa |

```python
from sklearn.metrics import cohen_kappa_score, confusion_matrix
import numpy as np
import pandas as pd

a = df["score_annotator_a"]
b = df["score_annotator_b"]

# 有序档位用 quadratic 加权
qwk = cohen_kappa_score(a, b, weights="quadratic")
plain = cohen_kappa_score(a, b)
agree = (a == b).mean()

print(f"完全一致率: {agree:.1%}")
print(f"Cohen's Kappa: {plain:.3f}")
print(f"Quadratic Weighted Kappa: {qwk:.3f}")

# 混淆矩阵 —— 比单个数字有用得多
cm = pd.DataFrame(confusion_matrix(a, b, labels=[1,2,3,4]),
                  index=[f"A={i}" for i in [1,2,3,4]],
                  columns=[f"B={i}" for i in [1,2,3,4]])
print(cm)
```

**解读参考**（Landis & Koch 惯例，只是参考不是法律）：

| Kappa | 解读 |
|---|---|
| < 0.40 | 差 —— rubric 有严重问题 |
| 0.40–0.60 | 中等 —— 还不能开工 |
| 0.60–0.80 | 好 —— 可以开始正式标注 |
| > 0.80 | 很好 |

### 4.5 Kappa 低了怎么办：看混淆矩阵找模式

不要盲目改 rubric。先分类诊断：

| 混淆矩阵的样子 | 诊断 | 处理 |
|---|---|---|
| 分歧集中在**相邻两档**（如 3 和 4） | 档位边界模糊 | 补该边界的锚点例子，或合并档位 |
| 一方**系统性偏高**（矩阵偏向一侧） | 严格程度不同 | 讨论对齐基准，不是改 rubric |
| 分歧集中在**某个意图类型** | 该场景标准缺失 | 为该场景补专门条款 |
| 分歧**随机分布** | rubric 整体太抽象 | 大改：拆维度、加锚点 |
| 分歧集中在**对抗类 case** | 对抗行为的期望没定义清楚 | 明确"纠正前提""澄清歧义"的具体判定 |

**真实经验**：第一版 rubric 的 Kappa 在 0.4–0.5 很正常。做到 0.7+ 通常需要 2–3 轮迭代。**把这个迭代过程完整记录下来，它就是你阶段 2 的核心作品。**

## 五、W4–W5：judge 搭建与校准

### 5.1 judge 的四种形态

| 形态 | 做法 | 适用 | 缺点 |
|---|---|---|---|
| **Pointwise 打分** | 给单个答案打 1–4 分 | 绝对质量、回归监控 | 绝对分数不稳定，模型版本变了分数会漂 |
| **Pairwise 比较** | 给两个答案判优劣 | A/B 对比、模型选型 | 有位置偏见；只得相对结论，不知绝对水平 |
| **Reference-based** | 对照 gold_answer 打分 | 有标准答案时 | 会惩罚"不同但同样好"的答案 |
| **Rubric-based 分维度** | 按 rubric 逐维度打分 | **本阶段主用** | prompt 长、成本高 |

**建议组合**：日常回归用 rubric-based pointwise；做 A/B 决策时用 pairwise 复核。

### 5.2 已知偏差与对策（必须掌握）

| 偏差 | 表现 | 对策 |
|---|---|---|
| **位置偏见** position bias | pairwise 时倾向选第一个（或第二个） | **交换顺序各跑一次**，只有两次结论一致才算数，不一致记为平局 |
| **长度偏见** length bias | 倾向给长答案高分 | rubric 明确写"长度不是评分依据，冗余扣可操作性分"；报告里同时看长度与分数的相关性 |
| **自我偏好** self-preference | judge 偏好与自己同家族模型的输出 | **judge 用与被测模型不同家族的模型**；做模型选型时尤其重要 |
| **分数集中** | 大量给 3 分，区分度低 | 强制分维度；要求先写理由再给分；给锚点 few-shot |
| **权威/格式偏见** | 带 markdown 标题、列表的答案得分更高 | rubric 明确格式只影响格式维度 |
| **顺从偏见** sycophancy | prompt 里暗示了期望答案，judge 顺着来 | judge prompt 里不要透露哪个是新版本/基线 |

**位置偏见的处理代码**：

```python
async def pairwise_judge(question, answer_a, answer_b) -> str:
    """返回 'A' / 'B' / 'TIE'，双向跑消除位置偏见。"""
    r1 = await _judge_once(question, answer_a, answer_b)   # A 在前
    r2 = await _judge_once(question, answer_b, answer_a)   # B 在前

    # r2 的结论要翻转回来
    r2_flipped = {"第一个": "B", "第二个": "A", "平局": "TIE"}[r2]
    r1_norm = {"第一个": "A", "第二个": "B", "平局": "TIE"}[r1]

    return r1_norm if r1_norm == r2_flipped else "TIE"
```

**顺带一个有用的副产品**：统计两次结论不一致的比例，这就是你的 judge 的**位置偏见强度**。超过 20% 说明这个 judge 不可用。

### 5.3 judge prompt 的五个迭代技巧

按效果排序：

**1. 先理由后分数（最有效）**

让 judge 先写分析再给分，而不是直接输出数字。强制它"想一想"。

**2. 分维度打分**

一次输出多个维度分，而不是一个总分。每个维度的判断都更聚焦。

**3. 加锚点 few-shot**

把 W3 标注时的争议 case 和边界例子放进 prompt，特别是**你和同事分歧最大的那几条**——那正是标准最模糊的地方。

**4. 结构化输出**

强制 JSON，方便解析且减少跑题。

**5. 类别路由**

不同 category 走不同判定逻辑（无答案题只判是否拒答，前提错误题只判是否纠正）。

```python
JUDGE_PROMPT = """你是一名严格的客服问答质量评审员。请按照下面的评分规范，对 AI 助手的回答打分。
```

### 5.5 校准：怎么算 judge 准不准

**核心思路：把 judge 当成一个分类器，用人工标注当 ground truth。**

```python
# eval/calibrate.py
import numpy as np
import pandas as pd
from scipy.stats import spearmanr
from sklearn.metrics import cohen_kappa_score, confusion_matrix, classification_report


def calibration_report(human: pd.Series, judge: pd.Series, dim: str) -> dict:
    """单个维度的校准指标。"""
    mask = human.notna() & judge.notna()
    h, j = human[mask], judge[mask]

    rho, p = spearmanr(h, j)
    return {
        "dimension": dim,
        "n": len(h),
        "exact_agree": (h == j).mean(),
        "within_1": (abs(h - j) <= 1).mean(),      # 相差不超过一档
        "qwk": cohen_kappa_score(h, j, weights="quadratic"),
        "spearman": rho,
        "spearman_p": p,
        "judge_mean": j.mean(),
        "human_mean": h.mean(),
        "bias": j.mean() - h.mean(),               # 正=judge 偏松，负=偏严
    }


def pass_fail_report(human: pd.Series, judge: pd.Series, threshold: int = 3):
    """二值化后看漏判/误判 —— 比相关系数更贴近业务。"""
    h_pass = (human >= threshold).astype(int)
    j_pass = (judge >= threshold).astype(int)
    cm = confusion_matrix(h_pass, j_pass)
    tn, fp, fn, tp = cm.ravel()
    return {
        "漏判率(人判不合格但judge放行)": fp / (fp + tn) if (fp + tn) else 0,
        "误判率(人判合格但judge拦截)": fn / (fn + tp) if (fn + tp) else 0,
        "confusion_matrix": cm,
        "report": classification_report(h_pass, j_pass,
                                        target_names=["不合格", "合格"]),
    }
```

**该看哪个指标？**

| 用途 | 主看 |
|---|---|
| judge 能否用于回归监控 | **QWK ≥ 0.6**，且 bias 绝对值小 |
| judge 能否用于 A/B 决策 | **Spearman ≥ 0.7**（只要排序对就行，绝对值可以有偏） |
| judge 能否用于线上卡点 | **漏判率**（放行了该拦的）—— 这是业务最关心的 |

**一个重要区分**：judge 有系统性偏差（总比人高 0.4 分）**并不致命**，只要偏差稳定，做 A/B 对比时会抵消。致命的是**排序错**——judge 认为 A 比 B 好，人认为相反。

所以：**做回归和 A/B，优先保证 Spearman；做绝对卡点，才需要 QWK 和低 bias。**

### 5.7 judge 校不准怎么办

如果迭代 5 轮 QWK 还在 0.5 以下，**问题可能不在 judge**：

| 可能原因 | 怎么确认 | 处理 |
|---|---|---|
| **rubric 本身模糊** | 人人之间的 Kappa 也低 | 回 W3 重做 rubric。**judge 与人的一致性不可能超过人与人的一致性**，这是天花板 |
| 任务本身高度主观 | 人人 Kappa 也就 0.5 左右 | 接受较低上限，或改用 pairwise（相对判断比绝对打分容易对齐） |
| 人工标注质量差 | 同一人隔日重标不一致 | 重新培训标注，或找领域专家 |
| judge 模型能力不足 | 换更强模型后显著提升 | 提升 judge 模型档次，或对难例走人工 |
| 某一类 case 拖累 | 分 category 算 QWK | 该类单独处理或单独走人工 |

**"人与人的 Kappa 是 judge 的天花板"** —— 这句话要记住，面试里说出来很有说服力。

### 5.8 成本与分层策略

judge 不必对所有 case 一视同仁：

```
全量 case
   ↓
确定性检查（拒答检测、引用提取、格式校验）—— 免费，先过一遍
   ↓ 通过的
小模型 judge 粗筛 —— 便宜
   ↓ 分数在边界区间（如 2.5–3.5）的
大模型 judge 精判 —— 贵但只跑 20%
   ↓ 仍然拿不准 / 涉及高风险类别
人工复核 —— 最贵，只跑 5%
```

这套级联在阶段 5 做线上评测时会救命。

## 六、验收自测

**1. judge 和人工的一致性，天花板是什么？**
人与人之间的一致性。如果两个标注者的 Kappa 只有 0.5，judge 不可能稳定超过它。所以 Kappa 低时应该先修 rubric，不是先调 judge prompt。

**2. 有序档位为什么用 quadratic weighted kappa，不用普通 Kappa？**
普通 Kappa 把"3 判成 4"和"1 判成 4"视为同等分歧。有序分数里，相邻档的分歧远没有跨档严重，加权 Kappa 能正确反映这一点。

**3. judge 总比人高 0.4 分，这个 judge 能用吗？**
看用途。做 A/B 对比和回归趋势，可以用——系统性偏差在对比时会抵消，关键看排序相关性（Spearman）。做绝对阈值卡点则不行，会大量漏判。

**4. pairwise 判优劣时怎么消除位置偏见？**
交换两个答案的顺序各跑一次，只有两次结论一致才采信，不一致记为平局。两次不一致的比例，就是位置偏见强度的度量。

**5. 为什么 judge 不该用和被测模型同家族的模型？**
自我偏好偏差——模型倾向于给自己家族的输出打高分。做模型选型时会得出错误结论。

**6. 评测集怎么证明有代表性？**
和线上真实 query 做分布对齐：意图分布偏差、长度分布 KS 检验、语义聚类覆盖率。刻意上采样高风险类别是允许的，但必须在报告里说明理由。

**7. 修改了评测集之后，新旧分数能直接比较吗？**
不能。必须标注分数对应的评测集版本。这也是评测集需要严格版本化的原因。

## 七、常见坑

| 坑 | 后果 | 防范 |
|---|---|---|
| 不做人工标注直接上 judge | 无法知道 judge 准不准，整个评测体系是空中楼阁 | 人工标注是地基，没有捷径 |
| 在同一批 20 条上反复调 rubric | 过拟合，换新数据一致性立刻掉 | 每轮换新样本 |
| 用 1–10 分档 | 人类一致性崩溃 | 3–5 档 + 锚点 |
| 只给总分不分维度 | judge 难对齐，低分时无法定位 | 分 3–4 个维度 |
| judge prompt 里暗示了哪个是新版本 | 顺从偏见，A/B 结论失真 | 盲评，answer 来源不透露 |
| 只报 Kappa 不看混淆矩阵 | 不知道分歧的模式，改进无从下手 | 永远配混淆矩阵一起看 |
| 忽略过度拒答 | judge 只罚幻觉不罚保守，系统被调成什么都不敢答 | rubric 里明确过度拒答的扣分 |
| judge 用同家族模型 | 自我偏好，选型结论错误 | 换家族；关键决策用两个不同 judge 交叉 |
| 评测集进了微调数据 | 分数虚高且无法察觉 | 评测集目录标注隔离，建立流程约束 |
